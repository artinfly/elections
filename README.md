# elections — учёт голосования работников

Веб-сервис на Django + PostgreSQL. Хранит список сотрудников из Excel-выгрузки,
позволяет отмечать запланированный способ голосования и фактическую явку,
принимает отчёты штаба и строит сводные отчёты в Excel.

## Возможности

- **Способ голосования** — план по каждому сотруднику: ДЭГ, свой участок,
  участок на предприятии (УИК-УВЗ), участок 19 округа; отметки регистрации
  и «Отсутствие по уважительной причине».
- **Явка** — отметка «проголосовал» по одному человеку или по всему фильтру;
  плашки со статистикой и окно с явкой по участкам (УИК).
- **Загрузка** — список сотрудников, явка из архива отчётов штаба (с датой и
  временем), кастомный сводный отчёт, отметки «Голосование через ответственного».
- **Отчёты** — сводки по цехам и производствам, архивы по цехам, конструктор
  отчёта по фильтрам (по людям или по производствам, обычный, компактный и ВН).
- **Админка** — сотрудники с ручными отметками, архив уволенных, пользователи
  с подтягиванием ФИО из кадрового API.

## Стек

Python 3.13, Django 6, PostgreSQL, openpyxl, whitenoise, htmx. Фронтенд без
сборки: Bootstrap и htmx лежат файлами в `election_statistics/static/vendor/`.

## Быстрый старт

```bash
python -m venv .venv
.venv\Scripts\activate            # Windows; в Linux: source .venv/bin/activate
pip install -r requirements.txt
copy .env.example .env            # и заполните значения
python manage.py migrate
python manage.py createsuperuser
python manage.py setup_groups
python manage.py runserver
```

Сайт открывается по адресу http://127.0.0.1:8000/, админка — `/admin/`.

## Настройки

Пароли, ключ и адреса в код не пишутся: `elections/settings.py` берёт их из
файла `.env` (в git не попадает, образец — `.env.example`).

| Переменная | Что это |
| --- | --- |
| `DEBUG` | `True` только на машине разработчика |
| `SECRET_KEY` | ключ Django; на сервере обязателен свой |
| `ALLOWED_HOSTS` | адреса сайта через запятую |
| `DB_NAME`, `DB_USER`, `DB_PASSWORD`, `DB_HOST`, `DB_PORT` | подключение к PostgreSQL |
| `HR_SERVICE_API_URL` | адрес кадрового API для админки |

При `DEBUG=False` статику раздаёт whitenoise, её нужно собрать:
`python manage.py collectstatic`.

## Страницы

| Адрес | Что показывает |
| --- | --- |
| `/` | способ голосования: плашки и таблица с простановкой |
| `/elections/` | явка: плашки, таблица, массовая отметка |
| `/upload/` | загрузка файлов |
| `/export/` | конструктор отчёта и готовые выгрузки |
| `/login/` | вход; выход — кнопкой в меню |

Плашки считаются по текущему фильтру. После простановки способа или явки
страница не перезагружается: счётчики обновляются запросом с теми же фильтрами.

## Способ и явка

| Код | Что значит |
| --- | --- |
| `deg` | ДЭГ, дистанционное электронное голосование |
| `uik` | свой участок |
| `uvz` | участок на предприятии (УИК-УВЗ) |
| `u19` | участок 19 округа |
| пусто | не выбран |

Полей два: `method` — где человек планирует голосовать, `voted_method` — где
проголосовал. При отметке явки `voted_method` копируется из плана, при снятии
очищается, поэтому изменение плана не сдвигает уже поставленную отметку.
Если при поштучной отметке явки способ не выбран, ставится `uik`.

Ручные отметки: регистрация на ДЭГ и на УИК-УВЗ (только при соответствующем
способе), «Отсутствие по УП», «Открепился», «Не пойдёт», «Голосование через
ответственного». Повторная загрузка списка сотрудников их не стирает.

## Загрузка файлов

Загружать файлы может оператор (группа `operator`) или суперпользователь.

| Что | Формат |
| --- | --- |
| Список сотрудников | .xlsx; заголовки ищутся по названиям, ключ — `Таб№`. Колонки: Подразделение, Таб№, Фамилия, Имя, Отчество, Должность, Категория, Дата рождения, Регион, Город, Улица, Дом, УИК, Адрес УИК, Район, Округ |
| Явка из отчётов штаба | .zip с .xlsx: табельный номер, дата и время голосования |
| Кастомный сводный отчёт | .xlsx или .zip: план, регистрация, явка и отметки по шапке отчёта |
| Голосование через ответственного | .xlsx или .zip: колонки «Таб» и «Отметка»; шаблон — на странице отчётов |

Производство в файле сотрудников не приходит. Его проставляет команда, которая
читает справочник «цех — производство» из внешней базы (пароль спрашивается
при запуске):

```bash
python manage.py import_workshops --host <адрес> --dbname <база> --user <пользователь>
```

## Права доступа

| Роль | Права |
| --- | --- |
| суперпользователь | всё, включая админку |
| группа `operator` | загрузка файлов, шаблон «через ответственного» |
| группа `viewer` | только просмотр, без простановки |
| группа `uik_uvz_viewer` | только страница явки по сотрудникам УИК-УВЗ |
| прочие | просмотр, простановка способа и явки, выгрузка |

Вход обязателен на всех страницах: в базе хранятся персональные данные.

## Отчёты

| Отчёт | Что внутри |
| --- | --- |
| Сводная таблица (и без 19 округа) | строка на цех: план по способам, явка, через ответственного, процент |
| По производствам | цеха по производствам: работающих, проголосовавших, процент |
| Способы по производствам (и без 19 округа) | распределение планируемых способов |
| Архивы по цехам | ZIP, файл на цех: явка или выбор способа и список тех, у кого отметки нет |
| Конструктор по фильтрам | по людям или по производствам; колонки заданы списком `CUSTOM_COLUMNS` |
| УИК-УВЗ: оформили, но не проголосовали | список по цехам с подытогами |
| Полная таблица | все сотрудники со всеми полями |

Колонки способов считаются по плану (`method`), «Проголосовавшие» — по факту
(`voted`), поэтому их суммы не обязаны совпадать. Цеха без производства
собираются в группу «Без производства», номера цехов дополняются нулями до трёх
цифр — так же называются файлы в архивах (`007.xlsx`).
