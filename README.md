# elections

Учёт голосования работников. Принимает выгрузку Excel по сотрудникам, хранит её
в PostgreSQL, показывает статистику по способу голосования и явке. Способ и явку
можно проставлять вручную по каждому человеку или списком.

## Стек

Django 6, PostgreSQL, openpyxl, whitenoise. Frontend без сборки: Bootstrap лежит
файлом в `election_statistics/static/vendor/`.

## Развёртывание

```bash
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.txt
.venv/Scripts/python.exe manage.py migrate
.venv/Scripts/python.exe manage.py createsuperuser
.venv/Scripts/python.exe manage.py setup_groups
.venv/Scripts/python.exe manage.py runserver
```

`requirements.txt` — только то, что нужно для запуска. Инструменты форматирования
вынесены в `requirements-dev.txt`, он подтягивает основной файл.

### Установка без интернета

В `wheels/` лежат пакеты для офлайн-установки:

```bash
.venv/Scripts/python.exe -m pip install --no-index --find-links wheels -r requirements.txt
```

Готовую папку `.venv` переносить с другой машины нельзя — в ней записан
абсолютный путь к Python. Её создают заново на месте.

## Настройки

`elections/settings.py` читает значения из переменных окружения, а при их
отсутствии берёт значения по умолчанию:

| Переменная         | По умолчанию                                       |
| ---------------------------- | ------------------------------------------------------------- |
| `SECRET_KEY`               | небезопасный ключ для разработки |
| `DEBUG`                    | `1`                                                         |
| `ALLOWED_HOSTS`            | `localhost,127.0.0.1,testserver` через запятую  |
| `DB_NAME`                  | `elections`                                                 |
| `DB_USER`, `DB_PASSWORD` | `postgres`                                                  |
| `DB_HOST`, `DB_PORT`     | `localhost`, `5432`                                       |

Для боевой установки задают собственный `SECRET_KEY`, `DEBUG=0` и реальные
адреса в `ALLOWED_HOSTS`. При `DEBUG=0` статику раздаёт whitenoise, и её нужно
предварительно собрать:

```bash
.venv/Scripts/python.exe manage.py collectstatic
```

Пока `collectstatic` не выполнен, whitenoise при запуске предупреждает об
отсутствии каталога `staticfiles` — на работу в режиме разработки это не влияет.

Ответы сжимаются `GZipMiddleware`: страницы со списком работников ужимаются
примерно в десять раз.

## Страницы

| Адрес                | Что показывает                                                                     |
| ------------------------- | ----------------------------------------------------------------------------------------------- |
| `/`                     | способ голосования: плашки и таблица с простановкой |
| `/elections/`           | явка: плашки, таблица, массовая отметка                         |
| `/upload/`              | загрузка файла со списком работников |
| `/export/`              | выгрузка: два архива по цехам, сводная и полная таблицы |
| `/login/`, `/logout/` | вход и выход                                                                          |

Плашки считаются по текущему фильтру: сузил выборку по цеху — числа сверху
пересчитались по этому же цеху. После простановки способа или явки страница не
перезагружается, счётчики обновляются запросом с теми же фильтрами.

Плашка «УИК» кликабельна: открывает окно с распределением по участкам — сколько
человек приписано к каждому УИК, сколько из них проголосовало и какая явка.
Окно учитывает тот же фильтр, что и страница.

На странице «Выборы» два столбца: «Явка» — переключатель «проголосовал / не
голосовал», и «Где голосовал» — текст без кнопок. Место не выбирается руками:
при отметке явки туда подставляется способ, выбранный на первой странице, при
снятии отметки оно очищается. Если способ у человека не выбран, место остаётся
пустым.

## Формат файла

Строка заголовков ищется по названиям колонок, её положение в файле значения не
имеет. Берутся все колонки, кроме `№ п/п` и `CARD_ID`:

Подразделение, Таб№, Фамилия, Имя, Отчество, Должность, Категория,
Дата рождения, Регион, Город, Улица, Дом, УИК, Адрес УИК, Район, Округ.

Ключ — `Таб№`. Повторная загрузка обновляет существующие записи и **не стирает**
проставленные способ голосования и явку.

Загружается только этот файл. Способ голосования и явка проставляются вручную
на страницах сервиса.

## Способ голосования

| Код     | Что значит                                                              |
| ---------- | -------------------------------------------------------------------------------- |
| `deg`    | ДЭГ, дистанционное электронное голосование |
| `uik`    | обычный участок |
| `uvz`    | участок на предприятии |
| пусто | не назначено |

Коды заданы в `models.py` и используются как значения фильтра и в API.

Полей два. `method` — «Способ», где человек планировал голосовать; заполняется
только на странице «Способ голосования» и повторной загрузкой файла не стирается.
`voted_method` — где он проголосовал; отдельно не редактируется, при отметке явки
копируется из `method`, при снятии очищается. План при этом не меняется.

Разделение нужно потому, что план можно поменять после того, как человек уже
проголосовал, и прошлая отметка от этого не поедет.

Плашки на странице «Способ голосования» считаются по плану, на странице
«Выборы» — по факту.

## Права доступа

| Роль                           | Права                                                                            |
| ---------------------------------- | ------------------------------------------------------------------------------------- |
| суперпользователь | все страницы, включая загрузку                              |
| группа `operator`          | загрузка файлов                                                         |
| прочие                       | просмотр, простановка способа и явки, выгрузка |

Вход обязателен на всех страницах: в базе хранятся персональные данные —
ФИО, дата рождения и домашний адрес. Группа создаётся командой
`python manage.py setup_groups`.

## utils/archiver.py

`ReportArchiver` собирает несколько книг openpyxl и произвольных байтов в
zip-архив: `add_workbook`, `add_file`, `build_bytes`. Повторное имя внутри
архива без `overwrite=True` вызывает `ArchiveError`. На нём построена выгрузка
отчётов по цехам.

## Выгрузка

| Что | Что внутри |
| --- | --- |
| архив по явке | zip, по одному .xlsx на цех: сколько проголосовало и кто не пришёл |
| архив по способу | тот же вид, но считаются выбравшие способ и список без выбора |
| сводная таблица | один .xlsx: строка на цех, ДЭГ / УИК / УИК-УВЗ, явка, процент |
| полная таблица | один .xlsx: все колонки загрузки плюс план, явка и место |

Имя файла внутри архива — номер цеха из трёх цифр: `007.xlsx`, `097.xlsx`,
`130.xlsx`. Отчёт по цеху: заголовок с датой и номером, три числа и поимённый
список тех, у кого нужная отметка отсутствует. Оба архива строит одна функция,
различия режимов заданы в `REPORT_MODES`.

В сводной таблице три колонки способов считаются по **плану** (`method`), а
«Проголосовавшие» — по факту (`voted`), поэтому их суммы не совпадают. Поле
группировки — параметр `summary_table`, чтобы позже добавить разрез по
подразделениям без переписывания.

## Тесты

```bash
.venv/Scripts/python.exe manage.py test election_statistics
```

Проверяются доступ по ролям, разбор колонок файла-образца, сохранность способа
и явки при повторной загрузке, пересчёт плашек по фильтру. Тесты создают
отдельную базу и удаляют её после прогона.
